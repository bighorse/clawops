# 企业微信政策匹配：失败结果需推送给用户 — 给 2048 后端的改动说明

## 问题
企业微信里用户发起政策匹配后，机器人先回一句"正在为您处理「政策匹配」，请稍候，完成后会主动通知您"。
- **成功**时：SOP 调用 `save_match_result`，由后端推送小程序政策匹配结果卡片给用户。✅
- **失败**时（企业未收录 / 企业名与工商全称不符 / 政策库接口异常 / 处理超时）：**用户收不到任何后续消息，一直空等**。因为失败路径不会调 `save_match_result`，后端也就没有触发点去通知用户。

**真实案例**：用户匹配"拓尔思信息技术有限公司"。该企业其实已入驻（库中登记名为"拓尔思信息技术股份有限公司"，enterprise_id=16），但用户少打了"股份"，企业画像 API 精确匹配 → 返回 404。系统已判定"没找到该企业档案，请核对工商全称"，但这句提示**从未推给用户**，用户只看到"请稍候…主动通知您"然后再无下文。

## 需要后端增加的能力
一个"给指定企业微信用户推送一条文本消息"的接口——复用现有推卡片的同一条企微通道即可。建议：

```
POST {wecom_api_base}/agent/push_message
Content-Type: application/json
body: {
  "agent_user_info": "uin:xxxxxxxx",   // 与现有 save_match_result 的 agent_user_info 同格式
  "text": "<要发给用户的纯文本消息>"
}
```
效果：把 `text` 作为一条普通消息发送到该用户的企微会话。

## 我们（clawops/SOP）这边如何配合
接口就绪后，我们会在政策匹配 / 资质核查 SOP 的**任一失败终态**调用它，把用户能看懂的失败原因发过去，例如：
- **企业未收录 / 名称不符**：「没找到「<用户输入的名称>」的企业档案。请确认是否为工商登记全称（如带"股份""集团""（北京）"等），或该企业是否为怀柔科学城入驻企业，然后重试。」
- **政策库接口异常 / 超时**：「政策匹配这次没跑成功，请稍后重试。」

## 建议叠加（更稳，兜住极端情况）
上面依赖 SOP 进程正常走到失败分支再调接口。但若 SOP 进程本身卡死/超时（连失败消息都来不及发），用户仍会空等。为此，clawops 侧可在**任务到达终态时（含我们侧的超时判定）主动 POST 一个完成事件**到你们指定的 webhook，携带 `agent_user_info`、`status`、以及给用户的话，由你们统一投递到企微会话。

两种方式二选一或叠加：
- 方式 A（简单）：仅提供 `push_message` 接口，由 SOP 在失败时调用。
- 方式 B（兜底更全）：A + clawops 完成事件 webhook，覆盖 SOP 未能自行上报的超时/崩溃场景。
